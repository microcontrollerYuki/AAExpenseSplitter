- 币种代码与最小单位精度采用 ISO 4217；金额用整数最小单位解析、计算及存储，不能对所有币种固定乘 100。JPY 的整数输入、其他币种小数位校验、超限及舍入边界分别测试。币种信息依据 [ISO 4217 维护机构 SIX](https://www.six-group.com/en/products-services/financial-information/market-reference-data/data-standards.html)。

### 手续费与共享汇率的新增规则

- **C-10 / C-11 手续费**：原转账仅保存本金，手续费保存为唯一关联的普通支出子账，来源账户和币种与转出账户一致。来源实际减少本金加手续费，目标增加确认的入账本金；报表排除转账本金，只计费用支出一次。例如同币本金 100、费用 1、入账 100，来源扣 101，支出统计为 1。新增、修改、取消费用、删除和撤销原子维护双方，费用子账不能独立改写或关联 AA；撤销不得复活此前已取消的费用。迁移默认无费用，保留旧金额与关联，失败整项回滚。
- **C-12 共享汇率**：转账预填和报表估算共用服务，默认读取网络当前汇率，可手动覆盖、查看当前模式并恢复联网。缓存记录币种方向、精确比例、来源和获取 / 报价时间；超时、离线、无有效值及过期均明确提示，不能把过期值伪称当前联网结果，也不能覆盖手动值或已确认账单金额。缓存涉及 schema 时安全迁移并测试失败重试。供应商、端点与可用性在 C-12 实施时验证，当前仅列计划，不宣称已接入。
- **C-13 转账预填**：网络或手动汇率只生成候选，两侧实际额仍由用户确认；可直接修改实际入账额，已有历史双额优先回显。换账户、换方向或改本金后丢弃迟到响应并重新确认；备注 / 日期编辑保留确认，后续联网刷新不重算已保存账单。汇率用精确比例而非 double，处理双方最小单位差异、JPY 整数与明确舍入；离线或缺汇率时允许人工确认双额。
- **R-09 / R-10 总收支**：明细顶部月收入 / 支出 / 结余和图表总览共同复用 R-09 模型，默认按网络当前或手动设置的同一汇率快照折合 CNY，展示来源 / 时间和「报表估算」口径，不改账单原币或账户实扣 / 实收。每笔折算并只舍入一次，月摘要、分类、趋势、统计明细与后续日历复用同一笔折算值。缺汇率或未知历史代码列出未纳入的币种、笔数和原币金额，显示待补齐，不把部分合计称完整总额。明细月摘要和图表均可各自切换原币，筛选状态独立，切换保留各自日期与分类，账单列表继续全币种可见。
