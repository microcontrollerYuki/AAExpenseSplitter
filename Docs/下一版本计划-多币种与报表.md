## 已交付多币种规则

- 首批支持 CNY、USD、HKD、EUR、JPY、GBP，币种代码和最小单位精度依据 [ISO 4217 维护机构 SIX](https://www.six-group.com/en/products-services/financial-information/market-reference-data/data-standards.html)。金额以整数最小单位解析和存储，单笔限制为有符号 int64，聚合使用 BigInt；JPY 使用整数，其他币种按各自精度校验，非法、过精度、越界或超资源上限输入明确拒绝。
- 普通支出 / 收入直接点击金额后的币种代码切换，编辑回显原币种。切换保留输入数字、备注、日期和分类，不暗中换算；账户与实际额必须符合新的币种关系。
- 账户有固定币种，期初额及余额按该币种计算。任何账单引用，包括软删除或转入引用，都会限制改币种 / 删除，避免旧账被换绑。净资产当前分币种列出。
- 普通账单保存交易原币金额与账户实际收付款额；同币金额相等，跨币须输入并确认实际额。例如支出 USD 10.00、微信实扣 CNY 72.00，原币报表计 USD 10.00，微信余额减 CNY 72.00。修改影响双额关系的金额 / 类型 / 币种 / 账户后须重新确认。
- 本人转账使用真实账户，分别保存来源本金和目标实际入账额。同币本金等额，跨币分别按双方精度确认正数；改任一账户或本金后重确认入账额，备注 / 日期修改保留确认。已有跨币转账改为同币仍须确认，缺失历史入账额不猜测。
- 旧记录按 CNY 原值保留；安全升级、失败回滚及重试不改历史金额与关联。当前 schema v6 包含账户实际额、目标入账额和手续费关联，普通收支的目标转账额为空。
- 列表 / 详情分别显示原币和账户实际额、转账双方金额；金额缺失标为待确认。当前日 / 月摘要、分类及趋势按原币隔离，不能直接相加 USD 与 CNY 数字；查重按同类型、同原币金额及本地自然日隔离。
- 既有 AA 只接受 CNY 交易与 CNY 账户。普通外币账和本人跨币转账保留本机，不进入旧 AA 同步协议；不能仅加格式版本号就向旧客户端发送外币。旧 CNY 文件、结算及已结算历史保护继续回归。
- OCR 明确币种可预选，含糊的 `$` / `¥`、未知币种或不确定的实际额留待核对；识别回调不得覆盖用户后来输入。无障碍候选沿用同一规则，尚未接入。

## 转账手续费：C-10 / C-11 已完成

手续费集成在转账中，分别显示本金、来源币种手续费、总扣款和目标实际入账。费用可选支出一级 / 二级分类或未分类，按来源币种额外支付，不从双方本金差额推断。例如本金 100、费用 1、入账 100，来源扣 101，支出统计为 1。

- 原转账只保存本金，费用保存为唯一关联普通支出；余额扣本金与费用各一次，报表排除本金、只计费用一次。
- 新增、修改、取消、父账删除及撤销由专用事务维护。零费用不新建子账，软删除费用仍占用唯一关联，取消后重加复用原费用 ID；撤销父账不得复活此前取消的费用。
- 费用子账只读，须随合法父转账统一修改；不能独立改写、删除或关联 AA，分类转移仍保留 owner / 联删标记。
- 修改来源账户或币种后重确认正费用，即使来源 A → B → A 也不自动恢复；目标入账额确认独立维护。不得把旧币种最小单位重新解释为新币种金额。
- 保存校验父账、费用和双方账户的完整快照，拒绝陈旧覆盖、部分写入及重复保存。加载 / 重载 / 错误、异常关联和受保护 AA / 结算历史保持保护；旧差额不补算费用。

## 默认总收支：R-09 / R-10 待实现

当前原币统计继续可用。以下折算仅用于报表估算，不改历史原币、账户实际额或已确认转账双额。

- **R-09**：复用 R-01 不可变账单集合，按网络当前或手动设置的同一汇率快照折合 CNY。每笔精确换算、只舍入一次，月摘要、分类、趋势、明细及后续日历复用同一个逐笔折算值，保证分区与总额守恒。
- **缺失汇率**：缺率、未知代码列出未纳入的币种、笔数及原币金额，提示待补齐；部分合计不能称完整总额。过期状态如实展示，原币账和余额仍可使用。
- **R-10**：明细顶部月收入 / 支出 / 结余和图表总览共同复用 R-09 模型，默认折合 CNY，展示估算口径、来源和时间。两处均可各自切换指定原币，筛选状态独立，切换保留各自日期 / 分类；账单列表始终全币种可见。
- 专项覆盖 BigInt / 精度、逐笔舍入、收支及分类交集守恒、缺率 / 过期、两个默认入口、独立切换、加载失败、编辑刷新和全币种列表；双雷电核对同条件摘要 / 图表 / 明细一致，并回归原币报表及账户余额。
