## 最终目标与技术边界

用户启用后，从指定支付 App 的可见交易页面本地识别金额、方向、状态、时间、商户及来源，匹配账户与一级 / 二级分类。先交付“识别 → 待确认 → 入账”，再交付“按用户规则自动保存 → 可查看、修正与撤销”。正常退后台、记账界面未打开时也须支持受支持交易；系统强制停止等限制按 P7-01 如实显示恢复状态。

首批适配微信 / 支付宝的明确完成交易；识别结果默认普通收支，AA 仍由用户主动选择。节点不足时按设备能力补充本地截图 OCR；现有拍照 / 相册 OCR 只回填表单，不是该自动链路。

复用 Flutter / Riverpod、Drift、整数最小单位和现有 ML Kit。原生层持久化有界采集队列，Dart 统一解析 / 入账，后台消费不能依赖 MainActivity 或编辑页存活。涉及数据库变更时必须有安全迁移、回滚与历史关联测试。现有 AA 的 CNY 防护继续回归，增强能力延后。

- [ ] **AA-01 · 配对与身份隔离**：依赖 D-01、P2-02、P1-05。稳定 pairingId 与双方身份、旧关系归档、按关系导出，换绑不混合历史。专项覆盖换绑后旧文件、同口令不同伙伴、身份冲突及旧文件兼容 / 拒绝；双机互导核对旧组不进入新关系、余额与历史不变。

## P2：可靠候选与统一入账

P2-02 按当前阶段计划前移至 D-01 后；其余 P2 项仍在 AA 可信闭环后推进，不因服务抽取而整体勾选。

- [ ] **P2-01 · 统一识别结果模型**：沿用 C 的币种 / 整数最小单位 / 账户实扣额模型；分别记录交易时间与采集时间，并记录方向、状态、来源包名、交易标识、字段依据及缺失 / 冲突原因。专项覆盖多金额、优惠、余额、格式错误和未知方向 / 币种；雷电用调试样例查看现有 OCR 结果，不增加另一套金额计算。
- [ ] **P2-02 · 提取统一入账服务**：手动、OCR 和后续识屏共用校验、保存及 AA 处理，保留编辑关联。专项回归普通收支、转账、AA 新建 / 编辑及失败回滚；雷电完成原记账流程，金额与余额一致。
- [ ] **P2-03 · 持久候选收件箱**：新增候选状态及来源记录，支持待确认、已入账、已忽略、失败；保存候选本身不影响余额。专项覆盖升级、重启、状态转换及容量上限；雷电关闭再打开仍能看到候选。
- [ ] **P2-04 · 来源幂等与删除语义**：可靠交易键由平台、归属主体及交易标识组成；来源绑定与账单写入同一事务，以唯一约束处理并发。无可靠键只生成待确认候选；同日同金额不代表同一交易。专项覆盖重复事件、崩溃重试、跨午夜及真实同额两笔；雷电重复打开页面只生成一笔，忽略 / 删除后不会立即自动重建。
- [ ] **P2-05 · 候选核对与修正**：展示金额、方向、日期、商户、账户、分类和识别来源；支持修改、确认、忽略及失败重试。专项验证取消不入账、连续点击只保存一次、账户缺失和疑似已有手动账单需核对；雷电完成核对后入账并从明细再次编辑。

## P3：无障碍节点识屏闭环

- [ ] **P3-01 · 服务注册和控制页**：声明原生 `AccessibilityService`，引导用户在系统设置启用；显示真实启用 / 连接 / 暂停状态及监听应用范围。专项覆盖状态桥接和权限拒绝；雷电实际开启、暂停、关闭，关闭后不再产生候选。
- [ ] **P3-02 · 可见节点采集**：仅采集已启用应用的当前可见交易窗口，提取文本、描述及必要位置；排除本 App、密码输入和无关窗口，限制深度 / 数量。专项覆盖空根、重复节点、乱序及窗口切换；雷电测试 App 读到预期字段，切到其他页面不产生日志原文或账单。
- [ ] **P3-03 · 事件合并与过期结果丢弃**：页面稳定后识别，同一窗口事件合并，有界重试；切换应用、锁屏或暂停后丢弃旧回调。专项模拟事件风暴、慢解析和乱序返回；雷电连续滚动 / 返回不重复弹出候选，界面不卡顿。
- [ ] **P3-04 · 后台持久队列与桥接**：原生采集先持久化，再由统一 Dart 服务消费；候选持久写入 Dart 侧并完成幂等登记后回执，不等待用户人工确认，崩溃可重放且不重记。队列满时暂停并提示，不静默丢失已接收项。验证无界面 Flutter 执行路径、数据库并发及插件初始化。专项覆盖桥接断开、消费中止、队列满和重放；雷电移走 App 界面再识屏，重新打开后候选完整，自动保存前先证明后台服务可执行。
- [ ] **P3-05 · 首次端到端待确认**：指定页面 → 节点文本 → 解析 → 候选 → 核对 → 账单。专项验证端到端金额、来源和余额；雷电独立测试 App 走通，同时保留手动记账与现有 OCR 入口。

## P4：真实支付平台适配

- [ ] **P4-01 · 微信成功支出**：按真实目标版本的字段标签和页面结构解析实付金额、时间、商户、状态及可用交易键。专项覆盖订单额 / 实付额 / 优惠 / 余额并存及文本顺序变化；雷电或目标真机真实微信页面核对，不能只靠测试 App 标记完成。
- [ ] **P4-02 · 支付宝成功支出**：独立模板和样例，不套用微信布局。专项覆盖多金额、支付方式、版式变化和缺字段；真实支付宝页面端到端验证并记录版本。
- [ ] **P4-03 · 收入与非完成交易分流**：明确到账作为收入；待支付、失败、关闭、退款、充值 / 提现、转账进入对应待核对状态，不用负号或最大金额猜类型。本阶段仅开放口径明确的普通收支；退款关联和跨账户转账单独扩展后才可自动保存。专项分别覆盖上述状态；雷电核对失败页面不生成正式账单，收入不会成为支出。
- [ ] **P4-04 · 字段可信条件与版本降级**：为每个字段记录命中依据，多候选、缺日期 / 方向、来源冲突或未知版式必须待确认。专项使用正反例断言，不以金额候选第一项直接落账；雷电变更测试布局后可解释缺失字段并回到核对流程。

## P5：截图 OCR 补充

- [ ] **P5-01 · 按能力截图**：用户开启补充模式后，节点不足时才调用支持的无障碍截图接口；低版本、受保护窗口、权限撤销或截图失败均回到待确认 / 手动图片入口。专项覆盖能力判断和失败码；雷电验证可读截图与失败分支，不用 ADB 截图成功代替应用自身能力验收。
- [ ] **P5-02 · 节点 / OCR 合并**：复用本地中文 OCR，明确字段优先级与冲突；同一交易共用来源键。专项覆盖节点与 OCR 不一致、空白 / 旋转图片和资源释放；雷电节点不可读样例走截图识别，两种来源同时命中仍只记一笔。
- [ ] **P5-03 · 采集数据生命周期**：原始截图和文本默认仅作短时解析，及时清理；用户可清理候选和识别诊断，不影响正式账单及去重所需最小记录。专项覆盖取消、失败、重启清理；雷电检查缓存有界增长，日志不含完整交易原文。

## P6：按用户规则自动保存

- [ ] **P6-01 · 账户与分类规则**：用户可按来源、支付方式、交易 / 账户币种和商户设置优先级明确的映射，支持一级 / 二级；币种或实扣额不确定、有歧义或映射目标被删除时待确认。专项覆盖重叠规则、收入 / 支出隔离和无匹配；雷电修改规则后下一笔正确采用且历史账单不重分类。
- [ ] **P6-02 · 自动保存开关与准入条件**：默认待确认，用户可为指定平台启用自动保存；只接受支持的成功状态、可靠交易键、确定金额 / 方向 / 时间、有效账户分类及无冲突结果。专项覆盖每个拒绝条件与规则变更；雷电 App 界面未打开时符合条件自动入账，不符合条件留收件箱。
- [ ] **P6-03 · 入账反馈、撤销与修正**：使用可用的通知 / App 内记录显示结果，支持撤销及打开详情修改；通知被拒绝也能在 App 内追溯结果。专项验证撤销账务和来源状态一致、不被重放自动复建；雷电查看余额、撤销、重新识屏和手动修正。
- [ ] **P6-04 · 自动识别与 AA 共存**：识屏默认普通收支，用户在核对或编辑时主动标记 AA，经过统一入账服务。专项覆盖来源幂等、AA 分摊、退回与结算；两台雷电同步同一已识别账单，不重复生成本机账单或分摊组。

## P7：稳定交付

- [ ] **P7-01 · 生命周期恢复**：覆盖进程回收、服务重连、设备重启、覆盖升级、权限撤销及队列恢复；系统强制停止时显示需恢复的真实状态，不承诺绕过系统限制。专项验证中断重试和暂停状态持久化；雷电执行每类中断，恢复后不漏已持久化候选、不重记。

## 每个小点的固定交付流程

1. **确认范围与复现**：选一个 TODO ID，写清该点行为、依赖和验收样例；缺陷先复现，功能先准备正例、反例。不要把整阶段一次性合并。
2. **实现并重新审查**：检查本点全部 diff、关联数据、升级 / 回滚及 AA 影响；具备条件时增加独立复查，记录实际审查方式。新增分析问题本轮处理，当前既有 27 条 warning / info 单独记录，不宣称全部清零。
3. **专项与短回归**：跑受影响 Dart / Widget 测试及现有全量回归；改 Kotlin / 服务 / 截图时必须增加对应 Android 层验证。常规测试优先控制在 60 秒内，Dart 单例默认 20 秒超时，异步等待有上限；原生测试同样设上限。超时或失败先定位，不靠反复重跑掩盖问题，不跳过必测分支。首次构建 / 下载依赖耗时单独记录。
4. **构建并更新雷电**：构建包含本点的 APK，覆盖安装，保留现有数据；需要测试 App 时同时更新。原生服务的系统启停和截图调用须在真实安装包操作，不能只靠 mock 或 ADB 抓屏。
5. **实际操作验收**：执行本点雷电操作，以及手动记账 → 修改 → 明细 / 统计的短冒烟；AA 相关点增加双机验证。数据层步骤先测试规则并验证覆盖升级，交互接入后再补实际功能操作。
6. **记录再推送**：在 [开发进度](开发进度.md) 记录 TODO ID、审查、测试数量 / 耗时、设备与操作结果；通过后提交并推送用户指定的 `Glm5.3F` 开发分支。推送成功、远端提交一致后才勾选完成；失败项保持未完成。原始屏幕文本、真实交易号、同步文件、设备数据库、截图和运行日志不入仓库，测试只提交脱敏或合成样例。

## 当前验证环境与能力边界

2026-10-08 只读确认：雷电 `emulator-5554`、`emulator-5556` 均为 Android 14 / API 34；两台当前均未安装微信、支付宝。先用独立测试 App 验证服务和完整链路，真实平台步骤必须另补真实目标 App 验证。模拟页面测试通过不代表真实支付 App 已适配；开发验收不需要发起真实付款。

2026-10-09 复验：两台雷电的无障碍设置均可解析到系统设置 Activity；独立测试 App 六个场景均可重复打开，Canvas 交易信息可见但未出现在 UI 节点树。当前没有目标真机连接，未验证应用自身的无障碍服务或截图 / OCR 链路。

Android 节点读取须注册无障碍服务并配置读取窗口内容的能力，由用户在系统设置启用。[Android 官方服务说明](https://developer.android.com/guide/topics/ui/accessibility/service)

无障碍 `takeScreenshot` 从 API 30 提供，并需声明截图能力；受保护窗口等情况可返回失败，必须处理降级。当前 API 34 雷电适合验证该路径，低版本能力另设测试。[Android 官方截图 API](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService#takeScreenshot(int,%20java.util.concurrent.Executor,%20android.accessibilityservice.AccessibilityService.TakeScreenshotCallback))

## 最终验收标准

- 真实受支持平台上，完成交易后可识别正确金额、方向、时间、账户及分类；未完成或不确定的交易留待核对，不能误入账。
- 用户启用自动保存后，App 界面关闭仍能自动入账；暂停 / 撤销权限后停止，恢复后来源幂等仍有效。
- 重复事件、节点与 OCR 双命中、重启、升级、重导和相同金额的不同交易均按既定去重规则正确处理。
- 旧手动账、分类、余额、AA 份额与结算保持正确；识别账单可追溯、修改和撤销。
- 所有已交付小点有审查、专项测试、短回归、雷电操作及远端提交记录；真实版本适配、已知限制和未完成项如实可查。
