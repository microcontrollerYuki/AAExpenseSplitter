## 目标与范围

支出和收入均支持「一级 → 二级」，例如「餐饮 / 早餐」「工资 / 兼职」。最多两级，一级分类仍可直接记账。覆盖分类管理、手动记账、图片识别结果选择、历史账单编辑与展示、现有统计、AA 分类快照及匹配。

不扩展三级分类、任意批量历史账单重分类或分类云同步；转账和 AA 内部往来分类维持现状。不强制新增预置二级分类。2026-10-10 新要求增加二级跨父级迁移及删除时受控转移账单，见 [分类迁移计划](下一版本计划-分类迁移与明细日历.md) 的 P1-06～08；下述现有限制将在这些小点验收后替换。

## 使用规则

- **分类管理**：沿用「我的 → 分类管理」的支出 / 收入分组；一级带着二级成组显示，一级旁提供加号新增二级。新增窗口可选择所属一级；普通编辑保留归属，有效二级右侧提供独立迁移按钮。长按右侧手柄排序，一级移动整个组，二级仅在自己的一级下排序。错误在窗口内显示；异常旧归属单独兜底显示，不提供新增、拖动或修改，可删除未被引用的记录。
- **父子约束**：二级必须属于同类型的有效一级；禁止三级、自循环、跨支出 / 收入挂接。新增时可选父级；普通编辑保留父级，P1-06 通过独立窗口及专用事务迁移同类型二级，仍不允许切换类型；重名、目标失效或归属已变化时提示并保留窗口。
- **名称**：去除首尾空白后不能为空；同类型、同父级内不允许重名，不同一级下允许同名二级。完整路径用于区分，例如「餐饮 / 其他」与「交通 / 其他」。路径分隔符 ` / ` 不允许出现在新增或修改后的分类名称中；旧名称保留，歧义匹配按下文回退。
- **记账选择**：按用户参考截图，一级采用五列宫格；点击一级直接选中，并在该行下方展开浅灰二级宫格，小箭头指向所属一级。二级可选，点父格可回到一级；选二级后父格显示「一级-二级」，长名称省略并保留完整路径提示。分类图标始终保留原彩色，选中通过背景和文字提示，不切换灰度。切换支出 / 收入时重置不适用的选择，避免保存到另一类型。
- **编辑与 OCR**：旧账单回显原一级或二级；普通记账和 OCR 结果使用同一套选择规则。修改分类不清空金额、账户、日期和备注。识别仅能确定一级时保留一级，不猜测二级。
- **删除**：P1-07 / 08 已接入确认范围、选择已有 / 新增 / 未分类、原子转移全部引用再删除。窗口列出整组二级及活跃 / 已删除账单数量，带二级须明确勾选整个组；新分类可创建为一级或同类型另一一级下的二级。取消或失败不写入，不删除账单，不静默级联；陈旧范围须刷新并重新确认，受保护 AA / 结算关联仍拒绝。完整规则见新增计划。
- **展示**：二级账单在明细、详情及显示分类的其他入口使用完整路径；一级账单仍显示一级名称。长名称正常换行或省略，完整名称可在详情查看。

## 数据与旧版本兼容

现有 `Categories.parentId` 已能表达父子关系，`Bills.categoryId` 继续只保存实际选中的分类 ID，不另存一份一级 ID。基础分类层级无需增加数据库字段；实现时集中提供分类树、完整路径和归属一级的查询逻辑，供各入口复用。

- 现有一级分类、名称、ID、账单引用和金额保持不变，不自动拆分或重分类。
- 更新分类时明确保留父级，修复现有 `upsertCategory` 省略父级就写入空值的隐患。
- 同级排序以「类型 + 父级」为范围，事务内完成，不改动其他层级。
- 对异常旧数据（父级缺失、跨类型、循环）有界解析并显示兜底，不崩溃、不静默改写原始记录；新增或更新不允许写入这些状态。
- 统计与显示允许一级改名，但不改变账单分类 ID；AA 名称继续作为记录时快照，不随本机后续改名自动改写。

## 统计口径

现有支出分类图按一级汇总：一级直属账单加所有二级账单，每笔只计一次。点击一级可查看二级排行，以及一级直属账单组成的「未细分」项；没有二级的分类保持一级汇总展示。

例如「餐饮」直属 10 元、「早餐」20 元、「晚餐」30 元，一级餐饮合计必须为 60 元；展开为未细分 10 元、早餐 20 元、晚餐 30 元。收入的月摘要和趋势同样不漏计、不重复计；按新增要求，本版收入饼图由 R-04 实现，点击分类的收支明细窗口由 R-05 实现，多币种与其他报表见 [新增计划](下一版本计划-多币种与报表.md)。分类缺失时归入「未分类」；内部分类收入不计收入，真实 AA 支出、普通结算收支及历史内部分类支出延续既有统计口径。

R-09 / 10 交付后，明细顶部月收入 / 支出 / 结余和图表总览都默认使用同一网络当前或手动汇率快照折合 CNY，共用 R-09 模型；月摘要、分类图、排行、趋势与明细复用每笔同一个折算值并展示估算口径 / 时间。两处各自可切原币、筛选状态独立，账单列表继续全币种可见，不能直接相加不同原币数值。缺汇率及未知代码列出未纳入项，不把不完整合计标为完整总额。转账本金不进分类支出，C-10 / 11 的关联手续费仅作为普通支出计一次，金额折算不改账户实扣额或历史账单。

## AA 同步兼容

分类树和本机分类 ID 不随 AA 文件同步，双方仍各自管理分类。本版优先沿用已有 `categoryName` 快照保存显示路径，例如「餐饮 / 早餐」，避免仅凭「其他」等同名二级误配。

- 新客户端接收路径快照：仅在本机存在唯一完整路径时自动匹配支出分类；缺失或歧义时进入现有兜底分类 / 人工选择流程，不取第一条同名分类、不自动创建分类。
- 新客户端接收旧文件的单名快照：仅在本机支出分类中唯一匹配时采用；重名则回退。
- 旧客户端接收新路径快照：可展示路径，但不能保证自动匹配本机分类，可能回退到原有默认分类；金额、份额、确认和结算不受影响。必须用旧版 APK 实测，不能把「文件可导入」等同于「分类完全兼容」。
- 分类路径只改变展示和匹配，不改变结算关联、核销范围、金额分摊及重复导入的幂等性。若上述兼容实测失败，先调整快照方案并补测试，再交付。

## 完成标准

1. 支出和收入都能管理、选择、保存及再次编辑二级分类，一级直接记账可继续使用。
2. 升级不改变旧账单分类 ID、金额、账户余额和 AA 关联；非法层级及危险删除由数据层阻止。
3. 一级汇总等于直属账单与二级合计；月摘要、趋势和 AA 分摊口径保持一致。
4. 新客户端不会因同名二级导致 AA 错配；新旧文件可按上述兼容规则处理，重复导入和结算回归通过。
5. 每步均有复查、测试和雷电操作记录后才推送；最后更新版本号、使用说明及开发进度，才标记本功能完成。
