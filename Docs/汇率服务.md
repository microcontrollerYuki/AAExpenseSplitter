# 共享汇率服务（C-12）

本页说明当前实现的接口边界和维护规则。完成状态与双雷电验收证据以 [总 TODO](TODO-无障碍自动记账.md)、[开发进度](开发进度.md) 和 [测试说明](测试说明.md) 为准。

## 使用入口与范围

“我的 → 汇率设置”默认查看 USD → CNY，支持 CNY、USD、HKD、EUR、JPY、GBP 六币种。首次打开先读取本地缓存；无网络缓存或缓存过期时自动联网，页面重建不会重复发起初始化请求，也没有后台定时轮询。

- 可联网刷新、取消请求，或输入正十进制手动汇率；最多 18 位小数，拒绝零、负数和科学计数法。取消输入窗口不保存。
- 手动设置只覆盖选定币对及其反向。例如 USD → CNY 的设置同时用于 CNY → USD，不推导 EUR → CNY 等其他币对；联网刷新保留手动覆盖。
- “恢复网络汇率”移除该币对双向覆盖，再使用已有网络缓存，必要时刷新。网络仍不可用时明确显示无值或旧缓存，不承诺恢复后一定能取得新值。
- 同币种固定为 1，不允许手动覆盖。页面显示来源、报价日期、获取时间或手动更新时间；18 位小数的显示结果标记为约值。

**C-12 提供查询、设置和共享计算基础；C-13 已将联网预填接入跨币转账（经 `TransferRatePrefill` 冻结快照）；R-09 / R-10 已交付报表折算模型与明细 / 图表默认折合 CNY 总收支（`FrozenCnyQuotes` / `CnyConvertedBills`，见 [开发进度](开发进度.md)）。** 保存汇率不会修改账单、账户余额或历史转账金额。

## 网络来源与缓存

采用 Frankfurter 的 ECB 专用 v2 路由，获取每日参考数据，不能视为银行实时成交价。接口和 provider 路由见 [Frankfurter 官方文档](https://frankfurter.dev/)。当前请求：

```text
GET https://api.frankfurter.dev/v2/providers/ecb/rates?base=EUR&quotes=CNY,USD,HKD,JPY,GBP
```

请求的业务参数只有币种，不发送账单、账户、金额或备注。一次请求总超时为 **8 秒**；取消会关闭 HTTP 客户端。仅接受 HTTP 200，不跟随重定向；响应体上限 **32 KiB**，声明长度和流式接收均检查。

响应必须包含五条不同目标币种、同一报价日期、EUR 基准的有效正汇率，再补入 EUR = 1，组成完整六币种快照。缺失、重复、未知币种、未来报价或格式异常均拒绝整批更新，保留旧值。

| 项目 | 当前规则 |
|---|---|
| 报价日期 `quotedAt` | 数据提供者的 UTC 自然日，与本机获取时间分开保存 |
| 获取时间 `fetchedAt` | 本机完成获取时的 UTC 时间；页面按设备本地时间显示 |
| 获取缓存过期 | 距获取时间达到 24 小时 |
| 报价过期 | 距报价 UTC 自然日达到 7 天 |
| 时钟异常 | 获取时间超过当前时间 5 分钟或报价日在未来，拒绝采用 |

上述任一过期条件满足即标记过期。周末沿用最近报价不自动等于报价过期；但即使报价日期尚在 7 天内，超过 24 小时未获取也会标记缓存过期。网络失败时仍可查看旧快照，页面明确提示缓存状态；没有旧值时显示“暂无可用汇率”。手动覆盖优先于网络，不沿用网络缓存的过期标记，并显示其更新时间。

## 精度与本地持久化

`RateRatio` 使用约分后的 BigInt 分子 / 分母 `N/D`，含义是“1 原币主单位对应多少目标币主单位”。网络 JSON 数字从原始十进制字面值解析，避免先转为 double；缓存也保存十进制整数字符串分数。

最小单位换算只在最后一步舍入：

```text
目标最小单位 = roundHalfAway(
  原币最小单位 × N × 10^目标小数位 / (D × 10^原币小数位)
)
```

恰好半个最小单位时远离零舍入；JPY 为 0 位，其余当前支持币种为 2 位。反向取倒数、交叉网络币对用完整分数计算。页面的约值字符串只用于展示，不能重新解析为业务换算输入。

数据库沿用 schema 6，在 `meta_entries` 表的唯一键 **`exchange_rates.v1`** 保存完整版本化 JSON：`version`、`network`、`manual`。网络块显式保存 `source`、`base`、报价日期、获取时间和完整六币种分数；手动块保存方向、分数与更新时间。一次写入整个记录，成功后才发布新内存状态，不另建表或覆盖其他 meta。

未知版本、来源 / 基准不符、重复键、未知币种、损坏记录等均整条拒绝采用并单独提示，不静默回退为人民币或默认汇率。坏缓存不会在初始化时自动覆盖，需用户明确刷新或重新设置。写入失败保留原内存与原有效记录，设置窗口允许重试。

## 并发边界与后续接入

请求阶段允许取消或改用手动汇率；代次校验丢弃已取消或已替代请求的迟到结果。**网络结果进入原子缓存写入后即到达提交边界**：`loading` 结束、`saving` 开始，取消入口隐藏，页面的刷新 / 手动设置入口 / 恢复按钮禁用；已打开设置窗口的提交也有 `saving` 守卫。此阶段的已开始写入不会被假装取消；随后操作经串行队列处理。页面关闭后的异步回调不操作已销毁的 UI，服务销毁后不再发布状态。

C-13 已按此约束实现转账预填：`TransferRatePrefill` 在弹窗打开时一次性取得并冻结不可变 `RateQuote`，采纳与候选显示都基于同一快照；迟到刷新只影响后续候选。R-09 / R-10 已按同一约束交付报表折算：`FrozenCnyQuotes.capture` 一次同步读取冻结全部 →CNY 币对，明细 / 图表分区只经逐笔值复用。不得在同一次计算中反复读取可变网络状态，不得把后续刷新后的汇率反写历史账单。缺率 / 过期汇率的界面提示由 R-10 口径行实现。
